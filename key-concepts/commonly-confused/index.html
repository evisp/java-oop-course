    Commonly confused¶

    Pairs of ideas that look alike and are not

    All modules12 pairs

    Each pair puts the two ideas side by side, with code from our bank, then states the difference in one or two sentences. Read the question at the bottom of each pair and answer it before you open the answer.

    The first two, reference and object, and static and instance, are the ones students mix up most often. Start there.

    Module 1 · Objects and State¶

    Reference and object¶

    Reference

    The arrow a variable holds. Copying it is cheap and creates nothing.

    Account backup = ada;   // a new arrow
    vs

    Object

    The account itself, with its own fields. Only new creates one.

    new Account("AC-1001", "Ada Lovelace", 500.00)

    The differenceTwo variables can hold arrows to the same object. A change made through either name is a change to that one object.

    Check yourselfAccount a = new Account("AC-1001", "Ada Lovelace", 100.00); then Account b = a; and b.deposit(50.00);. What does a.getBalance() return, and how many accounts exist?

    150.0, and there is one account. b = a copied the arrow, not the account.

    L2.2 What a variable really holds

    static and instance¶

    Instance field

    Belongs to one object. Every account has its own balance.

    private double balance;
ada.getBalance();
    vs

    static field

    Belongs to the class. One copy, shared by every account.

    private static int lastNumberIssued;
Account.getAccountsOpened();

    The differenceAsk whether every object needs its own value. If yes, it is an instance field. If it is one fact about all of them together, it is static. A static method has no this, so it cannot use instance fields directly.

    Check yourselflastNumberIssued starts at 1000 and every constructor runs lastNumberIssued++. After three accounts are created, how many copies of the field exist, and what do they hold?

    One copy, holding 1003. Each account has its own balance, but they all share lastNumberIssued.

    L3.2 What belongs to whom

    Class and object¶

    Class

    The description, written once in a .java file.

    public class Account { ... }
    vs

    Object

    One thing made from that description while the program runs.

    new Account("AC-1001", "Ada Lovelace", 500.00)

    The differenceA class is like a blank form, and objects are the filled-in copies: one form, many copies, each with its own answers.

    Check yourselfA program declares class Account and calls new Account(...) three times. How many classes and how many objects are there?

    One class and three objects.

    L2.1 Your first class

    == and equals¶

    ==

    For objects, compares references. Are these the same object?

    ada == alan   // false: two objects
    vs

    equals

    Compares by the rule the class defines. Do these count as the same thing?

    a.equals(b)   // true for two equal Strings

    The differenceUse equals for String and for your own classes. For primitives such as int and double, == compares the values themselves.

    Check yourselfString a = new String("AC-1001"); and String b = new String("AC-1001");. What do a == b and a.equals(b) give?

    false, then true. They are two objects holding the same text.

    L2.2 What a variable really holds

    Field and local variable¶

    Field

    Declared in the class, outside every method. It belongs to the object.

    private String ownerName;
    vs

    Local variable

    Declared inside a method. It exists only while the method runs.

    double total = 0;   // inside getTotalBalance()

    The differenceWhen a parameter has the same name as a field, the parameter wins inside the method. this.ownerName reaches the field.

    Check yourselfA constructor contains ownerName = ownerName;. It compiles. What does the field hold afterwards?

    null. The line assigns the parameter to itself, so the field is never set. Write this.ownerName = ownerName;.

    L2.1 Your first class

    Constructor and method¶

    Constructor

    Runs once, through new. Same name as the class, no return type.

    public Account(String accountNumber, ...)
    vs

    Method

    Runs each time it is called. Always has a return type, even if void.

    public boolean deposit(double amount)

    The differenceAdding a return type turns a constructor into a method: public void Account(...) is a method that happens to share the class's name.

    Check yourselfThe class has only public void Account(String n, String o, double b). Why does new Account("AC-1001", "Ada Lovelace", 500.00) not compile?

    That declaration is a method, not a constructor. The class has no constructor that takes three arguments.

    L2.1 Your first class

    final and immutable¶

    final

    The field cannot be pointed at anything else once it has a value.

    private final List<Account> accounts
        = new ArrayList<>();
    vs

    Immutable

    The object itself cannot change after it is built.

    String name = "ada";   // no method changes it

    The differencefinal fixes the arrow; immutable fixes the object. A final list can still have accounts added to it.

    Check yourselfWith private final List<Account> accounts, can accounts.add(...) run? Can accounts = new ArrayList<>(); run?

    The first, yes: the list itself can change. The second, no: the field is final, so it cannot be pointed at another list.

    L3.2 What belongs to whom

    Returning false and throwing an exception¶

    Return false

    An ordinary no, which the caller should expect and handle.

    if (!account.withdraw(900.00)) { ... }
    vs

    Throw

    A request that should never have been made, which means a bug in the caller.

    throw new IllegalArgumentException(
        "Deposit must be positive: " + amount);

    The differenceNot having enough money is a normal answer, so withdraw returns false. A negative amount means the calling code is wrong, so the account throws.

    Check yourselfWhich of these should refuse with an exception: withdrawing more than the balance, or creating an account with a null owner name?

    The null owner name. Asking for more money than you have is an ordinary request that can simply be answered no.

    L3.1 Objects that refuse

    Array and ArrayList¶

    Array

    Fixed length, chosen when it is created. Read it with length.

    Account[] accounts = new Account[3];
    vs

    ArrayList

    Grows and shrinks. Read it with size(), change it with add and remove.

    List<Account> accounts = new ArrayList<>();

    The differenceBoth hold references to objects. Use an array when the size is fixed and known in advance, and a list when items come and go.

    Check yourselfaccounts was created with new Account[3], and all three places are used. What happens on accounts[3] = new Account("Grace Hopper", 1500.00);?

    An ArrayIndexOutOfBoundsException. The array cannot grow; its valid positions are 0, 1 and 2.

    L4.1 Many objects

    null and empty¶

    null

    No object at all. Any method call on it throws a NullPointerException.

    List<Account> accounts = null;
    vs

    Empty

    A real object with nothing in it. Its methods work and report zero.

    List<Account> accounts = new ArrayList<>();

    The differenceReturn an empty list rather than null, so the caller's loop simply runs zero times. For text the same holds: "" is an empty String, and null is no String.

    Check yourselfWhat does accounts.isEmpty() give when accounts is null?

    Neither true nor false: it throws a NullPointerException, because there is no list to ask.

    Module 2 · Designing with Objects¶

    Overriding and overloading¶

    Overriding

    Same name and same parameter types as an inherited method. Your version replaces it.

    @Override
public boolean equals(Object other)
    vs

    Overloading

    Same name, different parameter types. A second, separate method.

    public boolean equals(Account other)

    The differenceList.contains calls equals(Object). It never calls an equals(Account) overload, so the list keeps comparing identity. Writing @Override turns that mistake into a compile error.

    Check yourselfA class has @Override above public boolean equals(Account other) and no other equals. What happens?

    It does not compile. The method overrides nothing, because Object.equals takes an Object.

    L5.2 Object Equality

    Switch statement and switch expression¶

    Switch statement

    Runs code in each branch. It need not cover every case.

    switch (choice) {
    case "1" -> listCustomers();
    default -> System.out.println("No such option.");
}
    vs

    Switch expression

    Produces a value. Over an enum it must cover every constant.

    boolean allowed = switch (type) {
    case CHECKING -> balance - amount >= 0.00;
    case SAVINGS -> balance - amount >= 100.00;
    case TERM_DEPOSIT -> false;
};

    The differenceUse an expression when you are choosing a value. Adding a constant to the enum then turns every forgotten switch into a compile error instead of a silent default.

    Check yourselfA switch expression over AccountType covers CHECKING and SAVINGS only. What happens?

    It does not compile: the switch expression does not cover all possible input values.
