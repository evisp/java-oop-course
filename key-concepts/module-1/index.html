    Objects and State¶

    Key concepts from Module 1, weeks 1 to 4

    Module 120 conceptsThe lectures

    Week 1 · Thinking in objects¶

    Week 1

    Object

    Explain it in your own words, then turn the card.

    Object¶

    A thing in a running program that keeps its own data and offers actions on that data. Each bank account in the program is one object.

    Account ada = new Account("AC-1001", "Ada Lovelace", 500.00);
ada.withdraw(200.00);   // ask the object to act

    Often confused withClass. The class is the description; objects are made from it, and one class can produce any number of them.

    State and behaviour

    Explain it in your own words, then turn the card.

    State and behaviour¶

    An object's state is what it knows at this moment, held in its fields. Its behaviour is what it can do, written as its methods.

    private double balance;                    // state

public boolean withdraw(double amount) {   // behaviour
    ...
}

    Week 2 · Classes, objects and references¶

    Week 2

    Class

    Explain it in your own words, then turn the card.

    Class¶

    A description of one kind of object: which fields every object of that kind has, and which methods it can run. Writing a class creates no objects; new does.

    public class Account {

    private String accountNumber;
    private String ownerName;
    private double balance;

    // constructor and methods
}

    Often confused withObject. Account is written once; the bank creates thousands of account objects from it.

    ObjectConstructorFieldMethodL2.1 Your first class
    Week 2

    Field

    Explain it in your own words, then turn the card.

    Field¶

    A variable declared inside a class but outside every method. Each object gets its own copy, and it lives as long as the object does.

    public class Account {
    private double balance;   // every account has its own
}

    Often confused withLocal variable. A local variable is declared inside a method and disappears when the method ends.

    State and behaviourEncapsulationfinalL2.1 Your first class
    Week 2

    Constructor

    Explain it in your own words, then turn the card.

    Constructor¶

    Code that runs once, when new creates an object, to give its fields their first values. It has the class's name and no return type.

    public Account(String accountNumber, String ownerName,
               double openingBalance) {
    this.accountNumber = accountNumber;
    this.ownerName = ownerName;
    this.balance = openingBalance;
}

    Often confused withMethod. A constructor runs once per object, at creation. A method can be called on the object any number of times.

    ClassObjectthisL2.1 Your first class
    Week 2

    this

    Explain it in your own words, then turn the card.

    this¶

    Inside a constructor or method, this is a reference to the object the code is running on. this.ownerName means this object's field, even when a parameter has the same name.

    this.ownerName = ownerName;   // field = parameter

    Often confused withLeaving it out. ownerName = ownerName; assigns the parameter to itself, and the field keeps its old value.

    ConstructorFieldL2.1 Your first class
    Week 2

    Method

    Explain it in your own words, then turn the card.

    Method¶

    An action an object can perform, written inside its class. It can read and change the object's fields and can return a result.

    public boolean deposit(double amount) {
    if (amount <= 0) {
        return false;
    }
    balance += amount;
    return true;
}
    State and behaviourEncapsulationL2.1 Your first class
    Week 2

    Reference

    Explain it in your own words, then turn the card.

    Reference¶

    What a variable of a class type actually holds: an arrow to an object, not the object itself. Copying the variable copies the arrow, so both names reach the same object.

    Account ada = new Account("AC-1001", "Ada Lovelace", 500.00);
Account backup = ada;        // a second arrow, same account
backup.withdraw(200.00);
System.out.println(ada.getBalance());   // 300.0

    Often confused withObject. backup = ada creates no new account. Only new creates objects.

    ObjectnullPassing an object to a methodL2.2 What a variable really holds
    Week 2

    null

    Explain it in your own words, then turn the card.

    null¶

    The value of a reference that points at no object. Calling a method through it throws a NullPointerException.

    Account closed = null;
closed.getBalance();   // NullPointerException

    Often confused withEmpty. A null list is no list at all. An empty list is a real list with nothing in it.

    ReferenceL2.2 What a variable really holds
    Week 2

    Passing an object to a method

    Explain it in your own words, then turn the card.

    Passing an object to a method¶

    Java copies the value of each argument into the parameter. For an object that value is the reference, so the method works on the caller's object, not on a copy of it.

    public static void applyFee(Account account) {
    account.withdraw(5.00);
}

applyFee(ada);   // ada's balance drops by 5

    Week 3 · Protecting an object's state¶

    Week 3

    Invariant

    Explain it in your own words, then turn the card.

    Invariant¶

    A rule about an object's state that must hold from the moment it is constructed and after every method call. For an account: the balance is never negative.

    if (openingBalance < 0) {
    throw new IllegalArgumentException(
            "Opening balance cannot be negative: "
            + openingBalance);
}
    EncapsulationConstructorL3.1 Objects that refuse
    Week 3

    Encapsulation

    Explain it in your own words, then turn the card.

    Encapsulation¶

    Keeping an object's fields private, so the only way to change them is through methods that check the change first. The object can then keep its own invariants.

    private double balance;

public void deposit(double amount) {
    if (amount <= 0) {
        throw new IllegalArgumentException(
                "Deposit must be positive: " + amount);
    }
    balance += amount;
}

    Often confused withPrivate fields with a setter for each. A setter that accepts any value protects nothing.

    InvariantGetter and setterFieldL3.1 Objects that refuse
    Week 3

    Getter and setter

    Explain it in your own words, then turn the card.

    Getter and setter¶

    A getter returns a field's value. A setter changes a field, and should refuse values that break the object's rules. Write a setter only for a field that is allowed to change.

    public double getBalance() {
    return balance;
}

public void setOwnerName(String ownerName) {
    this.ownerName = requireText(ownerName, "Owner name");
}
    EncapsulationL3.1 Objects that refuse
    Week 3

    final

    Explain it in your own words, then turn the card.

    final¶

    A final field gets its value once, in the constructor, and can never be reassigned. Use it for facts that do not change, such as an account number.

    private final String accountNumber;

    Often confused withImmutable. A final field cannot be pointed at another object, but the object it points at can still change.

    Immutable objectFieldL3.2 What belongs to whom
    Week 3

    Immutable object

    Explain it in your own words, then turn the card.

    Immutable object¶

    An object whose state cannot change after it is built: every field is final and there are no setters. String is immutable; its methods return new strings.

    String name = "ada lovelace";
name.toUpperCase();          // returns a new String
System.out.println(name);    // ada lovelace
name = name.toUpperCase();   // keep the new one
    finalL3.2 What belongs to whom
    Week 3

    static

    Explain it in your own words, then turn the card.

    static¶

    A static field or method belongs to the class itself, not to any object. There is one copy, shared by every object, and you reach it through the class name.

    private static int lastNumberIssued = 1000;   // one for all

Account.getAccountsOpened();   // called on the class

    Often confused withInstance fields. Every object has its own balance; there is only one lastNumberIssued.

    Week 4 · Many objects¶

    Week 4

    List and ArrayList

    Explain it in your own words, then turn the card.

    List and ArrayList¶

    List describes what an ordered collection can do; ArrayList is a class that does it, and it grows as you add items. A list holds references to objects, not copies of them.

    List<Account> accounts = new ArrayList<>();
accounts.add(new Account("Ada Lovelace", 500.00));
accounts.get(0);    // the first account
accounts.size();    // how many there are

    Often confused withArray. An array's length is fixed when it is created. A list grows and shrinks.

    Referencefor-each loopHas-a relationshipL4.1 Many objects
    Week 4

    for-each loop

    Explain it in your own words, then turn the card.

    for-each loop¶

    A loop that visits every element of a collection in order, without an index. The loop variable holds each reference in turn, so you can call methods on the objects but cannot replace them in the list.

    for (Account account : accounts) {
    account.deposit(10.00);   // every account gains 10
}
    List and ArrayListL4.1 Many objects
    Week 4

    Has-a relationship

    Explain it in your own words, then turn the card.

    Has-a relationship¶

    One object keeps others in its fields and is responsible for them. A customer has accounts: it opens them, finds them and totals them, and no other class changes its list.

    public class Customer {

    private final List<Account> accounts = new ArrayList<>();

    public Account openAccount(double openingBalance) {
        ...
    }
}

    Often confused withIs-a, the relationship behind inheritance, which you meet in week 7. A customer has accounts; a customer is not an account.

    Week 4

    Defensive copy

    Explain it in your own words, then turn the card.

    Defensive copy¶

    Returning a copy of an internal list instead of the list itself, so the caller can read it but cannot add or remove items behind the owner's back.

    public List<Account> getAccounts() {
    return List.copyOf(accounts);
}
